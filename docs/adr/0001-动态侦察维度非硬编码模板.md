# ADR-0001: 动态侦察维度（非硬编码模板）

## Context

autodev 初始设计面临的问题是：任务的侦察维度应该硬编码为固定模板，还是由 LLM 根据当前任务动态生成？固定模板的好处是确定性高、可预测；坏处是适应不同任务时的灵活性不足，尤其在多领域任务（CAE mesh 重构 vs Web 微服务）之间切换时模板可能完全不匹配。

## Decision

采用动态分解方案。侦察维度由 LLM 在 RECON-PLAN 阶段根据当前任务生成，存储在 autodev.yaml 的 recon.dimensions 中。base taxonomy 仅作为种子提示，不强制。这一策略已被证明是有效的 PLAN-stage 策略。

## Consequences

- 优点：适应任务方差，不局限于预设模板
- 优点：侦察维度可审计（存储在 autodev.yaml 中）
- 代价：每次运行需 LLM 重新生成，增加一次 LLM 调用
- 代价：生成质量依赖 LLM 能力，低质量 LLM 可能产生无效维度
