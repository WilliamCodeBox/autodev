# ADR-0002: YAML 而非内存状态

## Context

autodev 的核心是状态机编排。状态应该保存在内存中（性能好、延迟低），还是持久化到磁盘文件？内存状态在进程崩溃时丢失，不支持异步协作（多人看到同一状态），也无法提供历史审计轨迹。

## Decision

使用 YAML 快照 + run.json append-only 日志。YAML 提供 queryable/assertable/recoverable 的状态源，run.json 提供历史重放能力。这与数据库 WAL + checkpoint 的模式一致。

## Consequences

- 优点：崩溃恢复 —— session 中断后下次可 resume
- 优点：审计 —— 每步操作有 run.json 可追溯
- 优点：异步协作 —— 多人/多 Agent 能看到同一 autodev.yaml
- 代价：每次 transition 需写磁盘，写入延迟比纯内存高
- 代价：并发写需原子操作保证一致性（atomicWriteFile）
